Agent support turns a coding agent into an API-capable collaborator that can scan routes, enrich specs, build flows, and debug failures — all backed by reviewable markdown files in your repo.

<CardGroup cols={2}>
  <Card title="Skills" icon="book-open">
    Markdown playbooks that teach agents the Trellis spec format, file layout, and how to choose the right approach for each task. All agents get skills.
  </Card>
  <Card title="Slash commands" icon="terminal">
    Four `/trellis-*` commands for Claude Code and Codex CLI: scan, enrich, flow, and debug — each one handles a complex task that benefits from LLM reasoning.
  </Card>
  <Card title="MCP server" icon="plug">
    Three structured tools for Claude Code: exec, flow, and author. Agents get typed results without parsing shell output.
  </Card>
  <Card title="Shared markdown source" icon="code-pull-request">
    Every agent change is a markdown file in `api-docs/`. Reviewable, diffable, committable. No hidden state.
  </Card>
</CardGroup>

## Install in one command

<Steps>
  <Step title="Install skills and slash commands">
    Run the installer from the root of your project. It auto-detects which agents are present and writes the correct files for each.

    ```bash
    trellis skills install
    ```

    The command writes skills and (for Claude Code / Codex CLI) slash commands to the directories each agent reads.
  </Step>

  <Step title="Verify">
    ```bash
    trellis skills list
    ```

    Example output:

    ```
    claude-code   detected   .claude/skills/trellis-sync.md
                             .claude/skills/trellis-debug.md
                             .claude/commands/trellis-scan.md
                             .claude/commands/trellis-enrich.md
                             .claude/commands/trellis-flow.md
                             .claude/commands/trellis-debug.md
    cursor        detected   .cursor/rules/trellis-sync.mdc
                             .cursor/rules/trellis-debug.mdc
    copilot       detected   .github/instructions/trellis-sync.instructions.md
                             .github/instructions/trellis-debug.instructions.md
    ```
  </Step>

  <Step title="Register the MCP server (Claude Code only)">
    The MCP server gives Claude Code structured access to spec execution, pipelines, and authoring — no terminal output parsing.

    ```bash
    claude mcp add trellis -- trellis mcp
    ```

    Verify:

    ```bash
    claude mcp list
    ```
  </Step>
</Steps>

## Per-agent install

<CodeGroup>

```bash Claude Code
trellis skills install --agent=claude-code
# Installs: 2 skills + 4 slash commands
# Locations: .claude/skills/, .claude/commands/
```

```bash Codex CLI
trellis skills install --agent=codex-cli
# Installs: 2 skills + 4 slash commands
# Locations: ~/.codex/skills/, ~/.codex/commands/
```

```bash Cursor
trellis skills install --agent=cursor
# Installs: 2 skills as .mdc rules
# Location: .cursor/rules/
```

```bash GitHub Copilot
trellis skills install --agent=copilot
# Installs: 2 skills as .instructions.md
# Location: .github/instructions/
```

```bash Antigravity
trellis skills install --agent=antigravity
# Installs: 2 skills
# Location: .agents/skills/
```

```bash OpenCode
trellis skills install --agent=opencode
# Installs: 2 skills
# Location: .opencode/skills/
```

</CodeGroup>

## Keep skills current

After upgrading Trellis, check whether installed skills match the current binary:

```bash
trellis doctor
```

To update stale skills automatically:

```bash
trellis doctor --fix
```

<Warning>
  Stale skills are the most common cause of agents missing new commands or writing files in unexpected ways. Run `trellis doctor --fix` after every Trellis upgrade.
</Warning>
