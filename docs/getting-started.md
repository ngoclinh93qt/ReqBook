# Getting started

This page walks through installing Trellis, creating a project, and running your first endpoint. For the full spec format see [Spec convention](spec/convention.md). For all CLI flags see [CLI reference](cli.md).

## Installation

### Cargo (recommended for Rust developers)

Requires Rust 1.75 or later.

```bash
cargo install trellis
```

### Shell installer (macOS and Linux)

```bash
curl -fsSL https://trellis.dev/install.sh | sh
```

The installer places the `trellis` binary in `~/.local/bin` and prints instructions to add it to your `PATH`.

### npm

```bash
npm install -g @trellistrellis-md
```

The npm package bundles a prebuilt binary and works on macOS, Linux, and Windows.

### Homebrew (macOS)

```bash
brew install trellis-md/tap/trellis
```

### Docker

```bash
docker pull ghcr.io/trellistrellis-md:latest
docker run --rm -v "$(pwd)":/work -w /work ghcr.io/trellistrellis-md:latest validate api-docs/
```

Replace `validate api-docs/` with any `trellis` subcommand and flags.

## Verify the installation

```bash
trellis version
```

Expected output:

```text
1.0.0
```

Run `trellis doctor` to check that the environment is set up correctly (see [Diagnose issues](#diagnose-issues) below).

## Creating your first project

Run `trellis init` in an empty directory or an existing project root:

```bash
mkdir my-api && cd my-api
trellis init --name=my-api --dev-url=http://localhost:8080
```

Use `--yes` to accept all defaults without prompts, which is useful in scripts:

```bash
trellis init --yes
```

### What gets created

`trellis init` writes the following files and exits without overwriting anything that already exists:

```text
api-docs/
├── README.md               # generated index, do not edit by hand
├── trellis.md              # project config (name, default env, defaults)
├── _shared/
│   └── env.md              # non-secret environment values (baseUrl, etc.)
├── apis/
│   └── posts/
│       └── get-posts.md    # example endpoint file
└── flows/                  # empty, ready for flow files
.gitignore                  # .env.local appended if not already present
```

`api-docs/README.md` is regenerated by `trellis index`. Never edit it directly.

`api-docs/trellis.md` is the project configuration file. Open it to set the default environment, global timeout, retry policy, and web preview port.

`api-docs/_shared/env.md` holds non-secret values such as `baseUrl` for each environment. Do not put tokens or passwords here.

The `posts/get-posts.md` example uses [JSONPlaceholder](https://jsonplaceholder.typicode.com) so you can execute it immediately without running a server.

## Validating specs

Validate a single file or the entire `api-docs/` directory:

```bash
trellis validate api-docs/
```

A clean project prints:

```text
valid: api-docs/ (4 markdown files, 12ms)
```

If any file contains an error, Trellis prints the file path, line number, and a suggested fix, then exits with code 2. If a secret is found, it exits with code 5. See the [exit codes table](cli.md#exit-codes) in the CLI reference.

## Executing an endpoint

Run the example endpoint that `trellis init` created:

```bash
trellis exec api-docs/apis/posts/get-posts.md --env=dev
```

Pass variables with `--var`:

```bash
trellis exec api-docs/apis/posts/get-posts.md --env=dev --var postId=5
```

You can pass `--var` multiple times. CLI variables override values from `env.md` and `.env.local`. See [Variable resolution priority](configuration.md#variable-resolution-priority) for the full order.

Use `--dry-run` to print the resolved request without sending it:

```bash
trellis exec api-docs/apis/posts/get-posts.md --dry-run
```

## Opening the web preview

`trellis serve` starts a local HTTP server and opens a browser view of your `api-docs/` directory. The preview renders markdown, shows request and response blocks, and lets you execute endpoints interactively.

```bash
trellis serve
```

By default the server listens on `http://127.0.0.1:8080`. Pass `--port` or `--host` to change the address:

```bash
trellis serve --port=9000
```

Pass `--env` to change which environment variables are loaded:

```bash
trellis serve --env=staging
```

The web preview reads the same markdown files as the CLI. There is no build step and no separate configuration.

## Diagnose issues

`trellis doctor` checks common setup problems and prints a summary:

```bash
trellis doctor
```

Example output:

```text
Trellis 1.0.0 (rust unknown)

Project
  ✓ api-docs/ exists
  ✓ .env.local in .gitignore
  ✓ All specs valid (4 markdown files)

Agents
  ✓ Claude Code (.claude/)
  ✗ Cursor (.cursor/)
  ✗ GitHub Copilot (.github/)

Network
  ✓ Can reach httpbin.org
```

Use `--fix` to automatically repair issues that have safe automated fixes, such as adding `.env.local` to `.gitignore`:

```bash
trellis doctor --fix
```
