# Trellis makes agents API-capable.

Most API tools are built around human UI state. Trellis is built around markdown files and structured tools, so agents can participate directly. They can read specs, create endpoint files, run requests, diagnose failures, and build workflows that humans review in the browser UI.

## Install agent support

One command installs support for detected agents:

```bash
trellis skills install
```

Or target a specific agent:

```bash
trellis skills install --agent=claude-code
trellis skills install --agent=codex-cli
trellis skills install --agent=cursor
trellis skills install --agent=copilot
```

Supported agents:

| Agent | Integration |
|---|---|
| Claude Code | Skills, slash commands, MCP setup command |
| Codex CLI | Skills and command-style guidance |
| Cursor | Rules in `.cursor/rules/` |
| GitHub Copilot | Instructions in `.github/instructions/` |
| Antigravity | Skills |
| OpenCode | Skills |

## Recommended Claude Code setup

Install skills:

```bash
trellis skills install --agent=claude-code
```

Register MCP:

```bash
claude mcp add trellis -- trellis mcp
```

Then keep the web UI open:

```bash
trellis serve
```

This gives you the best loop:

1. Agent uses MCP tools to read, author, validate, and execute specs.
2. You inspect the generated specs and responses in the browser UI.
3. Trellis stores the result as markdown in `api-docs/`.

## Available skills

| Skill | Use when |
|---|---|
| `trellis-author` | The user asks to add, scaffold, document, or update one endpoint spec. |
| `trellis-exec` | The user asks to test, run, hit, or verify one existing endpoint. |
| `trellis-flow` | The user asks to run or debug an existing flow. |
| `trellis-workflow` | The user asks to create or edit a multi-step workflow. |

<Tip>
  The skills intentionally separate authoring, execution, and workflow creation. This prevents an agent from running an endpoint when the user only asked to document it, or overwriting a workflow when the user only asked to execute it.
</Tip>

## MCP tools

After MCP registration, Claude Code can call Trellis without shell parsing:

| Tool | What it does |
|---|---|
| `trellis_list_specs` | List endpoint specs with method, path, and file path. |
| `trellis_read_spec` | Read a spec file as markdown. |
| `trellis_validate` | Validate a file or directory. |
| `trellis_exec` | Execute one endpoint spec. |
| `trellis_flow` | Run one flow. |
| `trellis_author` | Create a new spec, or update one only after explicit user approval. |

MCP mode is recommended because responses are structured JSON. Agents do not need to parse colored terminal output or guess where a file lives.

## Keeping agent support current

Run diagnostics after upgrading Trellis:

```bash
trellis doctor
```

If skills are stale:

```bash
trellis skills install
```

<Warning>
  Stale skills are the most common cause of agents generating old paths such as `api-docs/users/...` instead of the current `api-docs/apis/users/...`.
</Warning>
