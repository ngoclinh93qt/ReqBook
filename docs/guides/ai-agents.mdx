# Trellis makes agents API-capable.

Agents are great at writing code but struggle with API work they can't reliably run requests from inside the session, produce API specs that stay in sync with the code, or review results in a structured way.

Trellis gives agents the building blocks they need: markdown files they can read and write, tools that return structured results, and playbooks that know when to call the CLI and when to use LLM reasoning.

## The division of labor

The key design decision: not every operation needs an agent. Simple, deterministic operations belong in the terminal. Agents add value when a task requires reasoning about your codebase, your domain model, or the relationships between data.

| Operation | Where | Why |
|---|---|---|
| Init, serve, validate, exec, mock | Terminal | Fast, composable, no LLM needed |
| Scan routes and create specs | `/trellis-scan` | Needs to read source types and infer realistic field values |
| Enrich expected responses and tests | `/trellis-enrich` | Needs to understand field semantics, volatile vs stable values, domain edge cases |
| Build a workflow pipeline | `/trellis-flow` | Needs to reason about data dependencies between steps |
| Debug a failing endpoint or flow | `/trellis-debug` | Multi-step diagnosis with contextual interpretation |
| Execute a spec (structured result) | `trellis_exec` MCP | Returns compact JSON pass `verbose: true` for full payloads |
| Dry-run (resolve vars, don't send) | `trellis_exec` + `dry_run: true` | Catches missing variables before hitting the network |
| Check variable readiness | `trellis_vars` MCP | Shows what's resolved and what's missing before exec |
| Search specs by method/tag/path | `trellis_search` MCP | Compact index no file reading required |
| Run a pipeline (structured result) | `trellis_flow` MCP | Returns per-step state for programmatic debugging |
| Author a spec (with write guard) | `trellis_author` MCP | Validates before writing, refuses silent overwrites |
| Check execution trend | `trellis_history` MCP | Stable/improving/regressing over recent runs |
| Set session defaults | `trellis_session` MCP | Set env + vars once; all exec/flow calls inherit |
| Run multiple specs | `trellis_exec_batch` MCP | Summary table not N full JSON objects |

## Skills all agents

Skills are the "always-on" layer: installed to each agent's config directory, they activate automatically when API-related topics come up in the conversation. No explicit command needed.

Two skills are available:

- **trellis-sync** Decision tree for creating and maintaining `api-docs/`. Covers first-time init, route scanning, spec enrichment, and flow creation.
- **trellis-debug** Diagnose a failing endpoint or pipeline. Covers single-endpoint debugging, pipeline tracing, and spec validation.

Skills are installed via `trellis skills install` to agent-specific locations (`.claude/skills/`, `.cursor/rules/`, `.github/instructions/`, etc.).

## Slash commands Claude Code and Codex CLI

Four commands covering the tasks where LLM reasoning produces better results than a fixed script:

| Command | What it does |
|---|---|
| `/trellis-scan` | Reads your source code to produce specs with real field names and realistic examples not stubs |
| `/trellis-enrich` | Executes real endpoints or reads source types to fill `## Expected response` and write meaningful tests |
| `/trellis-flow` | Reasons about data dependencies to build a pipeline that actually captures and injects the right values |
| `/trellis-debug` | Diagnoses failing endpoints and pipelines with contextual interpretation of each error |

## MCP server Claude Code

Three tools that return structured JSON for the agent to act on programmatically:

| Tool | When to use |
|---|---|
| `trellis_exec` | Execute a spec and get a structured result with diff |
| `trellis_flow` | Run a pipeline and get per-step state |
| `trellis_author` | Write a spec with validation guard and overwrite protection |

## Recommended Claude Code setup

<Steps>
 <Step title="Install skills and slash commands">
 ```bash
 trellis skills install --agent=claude-code
 ```
 </Step>
 <Step title="Register MCP">
 ```bash
 claude mcp add trellis -- trellis mcp
 ```
 </Step>
 <Step title="Open the web preview">
 ```bash
 trellis serve
 ```

 Keep the preview open while the agent edits specs review and run changed files immediately in the browser.
 </Step>
</Steps>

With all three active:
- The agent knows Trellis conventions and makes good decisions without prompting (skills)
- You can trigger complex workflows precisely without writing long prompts (slash commands)
- The agent gets structured results without parsing terminal output (MCP)
