# MarkApiDown makes agents API-capable.

Agents are great at writing code but struggle with API work — they can't reliably run requests from inside the session, produce API specs that stay in sync with the code, or review results in a structured way.

MarkApiDown gives agents the building blocks they need: markdown files they can read and write, tools that return structured results, and playbooks that know when to call the CLI and when to use LLM reasoning.

## The division of labor

The key design decision: not every operation needs an agent. Simple, deterministic operations belong in the terminal. Agents add value when a task requires reasoning about your codebase, your domain model, or the relationships between data.

| Operation | Where | Why |
|---|---|---|
| Init, serve, validate, exec, mock | Terminal | Fast, composable, no LLM needed |
| Scan routes and create specs | `/mad` | Needs to read source types and infer realistic field values |
| Enrich expected responses and tests | `/mad enrich` | Needs to understand field semantics, volatile vs stable values, domain edge cases |
| Build a workflow pipeline | `/mad flow` | Needs to reason about data dependencies between steps |
| Debug a failing endpoint or flow | `/mad-debug` | Multi-step diagnosis with contextual interpretation |
| Execute a spec (structured result) | `mad_exec` MCP | Returns compact JSON — pass `verbose: true` for full payloads |
| Dry-run (resolve vars, don't send) | `mad_exec` + `dry_run: true` | Catches missing variables before hitting the network |
| Check variable readiness | `mad_vars` MCP | Shows what's resolved and what's missing before exec |
| Search specs by method/tag/path | `mad_search` MCP | Compact index — no file reading required |
| Run a pipeline (structured result) | `mad_flow` MCP | Returns per-step state for programmatic debugging |
| Author a spec (with write guard) | `mad_author` MCP | Validates before writing, refuses silent overwrites |
| Check execution trend | `mad_history` MCP | Stable/improving/regressing over recent runs |
| Set session defaults | `mad_session` MCP | Set env + vars once; all exec/flow calls inherit |
| Run multiple specs | `mad_exec_batch` MCP | Summary table — not N full JSON objects |

## Skills — all agents

Skills are the "always-on" layer: installed to each agent's config directory, they activate automatically when API-related topics come up in the conversation. No explicit command needed.

One skill covers the full workflow:

- **mad** — Project layout, endpoint spec format, Assertions operators, pipeline capture patterns, MCP tool reference, and routing rules for when to use each slash command.

Installed via `mad skills install` to agent-specific locations (`.claude/skills/`, `.cursor/rules/`, `.github/instructions/`, etc.).

---

## Slash commands — Claude Code and Codex CLI

Two commands covering the tasks where LLM reasoning produces better results than a fixed script:

| Command | What it does |
|---|---|
| `/mad` | Creates specs, enriches expected responses, and builds/runs pipelines — routes based on your argument |
| `/mad-debug` | Diagnoses failing endpoints and pipelines with contextual interpretation of each error |

---

## MCP server — Claude Code

Eight tools that return structured JSON for the agent to act on programmatically:

| Tool | When to use |
|---|---|
| `mad_exec` | Execute a spec and get a structured result with diff |
| `mad_flow` | Run a pipeline and get per-step state |
| `mad_author` | Write a spec with validation guard and overwrite protection |
| `mad_vars` | Check variable resolution before exec |
| `mad_search` | Find specs by method, path, or tag |
| `mad_history` | Check execution trend over recent runs |
| `mad_session` | Set env and vars once for all subsequent calls |
| `mad_exec_batch` | Run multiple specs and get a summary table |

## Recommended Claude Code setup

<Steps>
 <Step title="Install skill and slash commands">
 ```bash
 mad skills install --agent=claude-code
 ```
 </Step>
 <Step title="Register MCP">
 ```bash
 claude mcp add mad -- mad mcp
 ```
 </Step>
 <Step title="Open the web preview">
 ```bash
 mad serve
 ```

 Keep the preview open while the agent edits specs — review and run changed files immediately in the browser.
 </Step>
</Steps>

With all three active:
- The agent knows MarkApiDown conventions and makes good decisions without prompting (skill)
- You can trigger complex workflows precisely without writing long prompts (slash commands)
- The agent gets structured results without parsing terminal output (MCP)
