# API specs for vibe coding agents and the developers who review them.

Trellis turns API work into plain markdown files that your coding agent can understand, your browser can preview, and your CI can validate. The goal is simple: describe an API once, then let humans, agents, the web UI, and terminal commands all work from the same source.

## Why Trellis exists

Modern API work is no longer only a person clicking a request builder. A coding agent may discover a route, create the spec, run the endpoint, capture an ID, connect it into a workflow, and explain the failure. That workflow breaks down when the API tool stores state in a private app database or a format agents cannot reason about.

Trellis keeps the source of truth in markdown:

- Endpoint specs live in `api-docs/apis/<resource>/<method>-<slug>.md`.
- Workflows live in `api-docs/flows/<flow>.md`.
- Environment values live in `api-docs/_shared/env.md`.
- Project settings live in `api-docs/trellis.md`.

The same files are read by:

- the browser UI for interactive execution and editing,
- the Rust CLI for automation and CI,
- AI agent skills and MCP tools for vibe coding,
- humans in pull requests.

## Typical vibe coding loop

<Steps>
  <Step title="Ask your agent to add or scan API specs">
    Use a prompt such as:

    ```text
    Scan this project for API routes and add missing Trellis specs.
    ```

    Or:

    ```text
    Document POST /orders and make it runnable in Trellis.
    ```
  </Step>

  <Step title="Review in the web UI">
    Start the local preview:

    ```bash
    trellis serve
    ```

    Use the UI to inspect the generated markdown, try runtime-only params or headers, run the request, and compare the response.
  </Step>

  <Step title="Turn endpoints into a workflow">
    Ask the agent to connect specs:

    ```text
    Create a checkout flow: create customer, create order, capture orderId, then fetch the order.
    ```

    Trellis stores the workflow as markdown under `api-docs/flows/`, and the web canvas can edit the same file.
  </Step>

  <Step title="Commit markdown, not hidden state">
    Run validation before commit:

    ```bash
    trellis validate api-docs/
    ```

    Review the changed markdown files in your PR.
  </Step>
</Steps>
