# Agent-native across 6 coding tools, visual debugger, fast CLI, your entire API lives in plain markdown.

## How it works

Every API operation lives in a markdown file:

```
api-docs/
├── trellis.md # Project config and defaults
├── _shared/
│ └── env.md # Base URLs and environment variables
├── apis/
│ ├── users/
│ │ ├── get-user-by-id.md
│ │ └── create-user.md
│ └── orders/
│ └── post-orders.md
└── flows/
 └── checkout.md # Multi-step pipeline
```

The same files are used by:

| Surface | What it does |
|---|---|
| `trellis exec` | Sends the HTTP request and diffs the response |
| `trellis serve` | Renders a browser UI for interactive testing |
| `trellis mock` | Serves recorded responses without a live backend |
| `trellis flow` | Runs a pipeline, captures values, injects them into later steps |
| Agent skills | Teaches agents the format, file layout, and how to validate changes |
| MCP tools | Lets Claude Code list, read, validate, execute, and author specs without shell parsing |
| CI | Validates all specs and exits non-zero on any failure |

## The vibe coding loop

<Steps>
 <Step title="Agent creates or updates specs">
 Ask your agent to document a route, import from curl, or scan the project for missing specs:

 ```text
 Scan this project for API routes and add missing Trellis specs.
 ```

 ```text
 Document POST /orders and make it runnable in Trellis.
 ```
 </Step>

 <Step title="Review in the browser UI">
 ```bash
 trellis serve
 # → Preview: http://127.0.0.1:8080
 ```

 Inspect the generated markdown, adjust runtime params, run the request, and compare the response against the expected value.
 </Step>

 <Step title="Build flows">
 Ask the agent to connect specs into a pipeline:

 ```text
 Create a checkout flow: create customer → create order, capture orderId → fetch order.
 ```

 The flow is saved as `api-docs/flows/checkout.md` and runnable from both CLI and browser.
 </Step>

 <Step title="Commit reviewable markdown">
 ```bash
 trellis validate api-docs/
 ```

 Specs are ordinary markdown. Every change is reviewable, diffable, and revertable in your PR.
 </Step>
</Steps>

## Without Trellis, agents work blind

When an agent needs to test an API endpoint without Trellis, it reads router files, middleware, env config, constructs a `curl` command, parses raw stdout, and throws everything away. The next session starts from zero.

| Task | Without Trellis | With Trellis |
|---|---|---|
| Test one endpoint | Read 3+ source files, construct curl, parse stdout (~500 tokens/call) | `trellis_exec spec.md` structured result (~50 tokens/call) |
| Debug multi-step flow | Write a temp script, manually chain requests, no trace on failure | `trellis_flow pipeline.md` per-step state, captured values |
| Detect a regression | Only after a bug report | `trellis validate` in CI fails before merge |
| Agent discovers APIs | Scan entire codebase (~10,000–50,000 tokens) | `trellis_search --tag auth` compact index instantly |
| Share tests with team | "Send me the curl" | Commit markdown, review in PR |
| Mock backend | Run live server or hardcode | `trellis mock` from recorded responses |

The setup cost is five minutes (`trellis init`). After that, every agent call costs ~10× fewer tokens and produces reviewable, reusable artifacts.

## Why not Postman, Insomnia, or Bruno?

<CardGroup cols={2}>
 <Card title="Agents need file-based tools" icon="robot">
 GUI tools store state in app databases or proprietary formats. Agents cannot read or write them reliably. Trellis specs are plain markdown any agent can read, create, and edit them.
 </Card>
 <Card title="Everything stays in the repo" icon="code-branch">
 Specs live in `api-docs/` alongside your code. Every API change goes through code review. No "export to share" step, no drift between the tool and the repo.
 </Card>
 <Card title="One source, every surface" icon="layer-group">
 The same file runs in the CLI, renders in the browser UI, serves the mock server, and validates in CI. You describe the API once.
 </Card>
 <Card title="No account, no cloud" icon="hard-drive">
 A single Rust binary. No signup, no workspace ID, no internet dependency at runtime. Works offline.
 </Card>
</CardGroup>
