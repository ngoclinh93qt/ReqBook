## Prerequisites

Trellis requires **Rust 1.75+** if you install via Cargo, or **macOS / Linux with `curl` and `sh`** if you use the shell installer.

<Note>
  Additional install methods — Homebrew, npm, Docker, and Windows MSI — are covered in the [Installation](/docs/installation) page.
</Note>

---

## Get up and running

<Steps>
  <Step title="Install Trellis">
    Choose your preferred install method:

    <Tabs>
      <Tab title="Shell installer">
        ```bash
        curl -fsSL https://trellis.dev/install.sh | sh
        ```

        The installer places `trellis` in `~/.local/bin` and prints instructions to add it to your PATH if needed.
      </Tab>
      <Tab title="Cargo">
        ```bash
        cargo install trellis
        ```

        Requires Rust 1.75 or later. Run `rustup update` if you need to upgrade.
      </Tab>
    </Tabs>

    Verify the install:

    ```bash
    trellis version
    # 1.0.0
    ```
  </Step>

  <Step title="Create a project">
    Scaffold a new Trellis project in any directory:

    ```bash
    mkdir my-api && cd my-api
    trellis init --name=my-api --dev-url=http://localhost:8080
    ```

    This creates the following structure:

    ```
    api-docs/
    ├── README.md
    ├── trellis.md
    ├── _shared/env.md
    ├── apis/posts/get-posts.md
    └── flows/
    .gitignore
    ```

    The `trellis.md` file is your project configuration. The `_shared/env.md` file holds non-secret environment variables. The generated `get-posts.md` example targets [JSONPlaceholder](https://jsonplaceholder.typicode.com) so you can run it immediately without a local server.

    {/* TODO: screenshot of terminal after trellis init showing created files */}
  </Step>

  <Step title="Validate your specs">
    Check that all endpoint files are well-formed before executing anything:

    ```bash
    trellis validate api-docs/
    ```

    Expected output:

    ```
    valid: api-docs/ (2 markdown files, 8ms)
    ```

    <Tip>
      Run `trellis validate` in CI as a fast pre-flight check — it parses every spec and catches malformed frontmatter or missing required sections without sending any HTTP requests.
    </Tip>
  </Step>

  <Step title="Execute an endpoint">
    The scaffolded example uses JSONPlaceholder, so it works immediately without running a local server:

    ```bash
    trellis exec api-docs/apis/posts/get-posts.md --env=dev
    ```

    Expected output:

    ```
    GET https://jsonplaceholder.typicode.com/posts
    status: 200
    duration: 180ms
    diff: passed
    ```

    Trellis resolves the `base_url` variable from `_shared/env.md`, sends the request, and diffs the response against the `## Expected response` section in the file.

    {/* TODO: screenshot of colored terminal output from trellis exec */}
  </Step>

  <Step title="Open the web preview">
    Start the local web UI to browse, run, and import specs interactively:

    ```bash
    trellis serve
    ```

    Opens [`http://127.0.0.1:8080`](http://127.0.0.1:8080) in your browser. From there you can browse all endpoint files, execute individual requests with the Run button, and import new specs from a curl command.

    {/* TODO: screenshot of trellis serve UI showing the endpoint list and run button */}
  </Step>
</Steps>
