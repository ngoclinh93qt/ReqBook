# Quickstart

This path is for a developer who wants MarkApiDown working with a coding agent and a browser UI in a few minutes. The terminal is still there for automation, but it is not the only interface.

---

## 1. Install MarkApiDown

<Tabs>
 <Tab title="Shell installer">
 ```bash
 curl -fsSL https://markapidown.net/install.sh | sh
 ```
 </Tab>
 <Tab title="Cargo">
 ```bash
 cargo install mark-api-down
 ```
 </Tab>
 <Tab title="npm wrapper">
 ```bash
 npm install -g mark-api-down
 ```
 </Tab>
</Tabs>

Verify the install:

```bash
mad version
```

---

## 2. Create a project

```bash
mkdir my-api && cd my-api
mad init --name=my-api --dev-url=https://jsonplaceholder.typicode.com --yes
```

MarkApiDown creates:

```text
api-docs/
├── README.md
├── mad.md
├── _shared/
│ └── env.md
├── apis/
│ └── posts/
│ └── get-posts.md
└── flows/
.gitignore
```

The generated endpoint uses JSONPlaceholder, so it can run immediately.

---

## 3. Open the web UI

```bash
mad serve
```

Open `http://127.0.0.1:8080`.

Use the browser UI to:

- browse endpoint files,
- switch environments,
- fill path params such as `postId`,
- add runtime-only headers or body overrides,
- run requests and inspect formatted responses,
- import an endpoint from cURL,
- open the flow canvas.

<Note>
 Runtime fields in the request builder are temporary. They do not change markdown files unless you switch to edit mode and save.
</Note>

---

## 4. Run the same spec from the terminal

```bash
mad exec api-docs/apis/posts/get-posts.md --env=dev
```

Expected output:

```text
GET https://jsonplaceholder.typicode.com/posts/1
status: 200
duration: 180ms
```

Dry-run shows the resolved request without sending it:

```bash
mad exec api-docs/apis/posts/get-posts.md --env=dev --dry-run
```

```text
GET https://jsonplaceholder.typicode.com/posts/1
status: DRY RUN
duration: 0ms
headers:
 accept: application/json
```

---

## 5. Install agent skills

```bash
mad skills install
```

Or choose one agent:

```bash
mad skills install --agent=claude-code
mad skills install --agent=cursor
mad skills install --agent=copilot
```

Now you can ask your coding agent:

```text
Add a MarkApiDown spec for GET /users/:userId and validate it.
```

Or:

```text
Create a flow that gets a post, captures userId, then gets that user.
```

---

## 6. Validate before commit

```bash
mad validate api-docs/
```

Commit the markdown files, not hidden app state.
