## Global flags

Every subcommand accepts these flags. They must be placed before the subcommand name.

| Flag | Type | Description |
|---|---|---|
| `--config <path>` | path | Path to `api-docs/mad.md`. Overrides the default discovery. |
| `--no-color` | bool | Disable ANSI color in output. Also respected if `NO_COLOR` is set in the environment. |
| `-v`, `--verbose` | bool | Enable verbose diagnostic output. |

## Exit codes

MarkApiDown returns stable exit codes you can reliably test for in CI scripts. See the [Exit codes reference](/docs/reference/exit-codes) for CI usage examples.

| Code | Name | Meaning |
|---|---|---|
| `0` | Passed | All checks passed, request matched expected response. |
| `1` | Test failed | Response did not match the expected response. |
| `2` | Invalid spec | Spec file has a structural, syntax, or missing-variable error. |
| `3` | Engine error | Internal request build failure; check protocol and request block. |
| `4` | Network error | Host unreachable, DNS failure, timeout. |
| `5` | Secret detected | A secret pattern found in a versioned markdown file; exits before any network request. |

## mad init

Scaffold a new `api-docs/` project in the current directory.

```bash
mad init [--name=<name>] [--dev-url=<url>] [--yes]
```

| Flag | Type | Default | Description |
|---|---|---|---|
| `--name` | string | interactive | Project name written into `mad.md`. |
| `--dev-url` | string | interactive | Base URL written into `_shared/env.md` for the `dev` environment. |
| `--yes` | bool | `false` | Accept all defaults without interactive prompts. |

Without `--yes`, MarkApiDown prompts for any missing values. `--yes` uses `my-api` and `http://localhost:8080` as defaults when no flags are provided.

<Note>
`mad init` does not overwrite existing files. If a file already exists, it exits with an error naming the conflicting file. It also appends `.env.local` to `.gitignore` if not already present.
</Note>

**Examples**

```bash
# Interactive
mad init

# Non-interactive
mad init --name=payments-api --dev-url=http://localhost:3000

# Accept all defaults in CI
mad init --yes
```

**Exit codes**: `0` on success, `3` on filesystem error.

## mad validate

Validate one endpoint file, one pipeline file, or all markdown files under a directory.

```bash
mad validate <path>
```

| Argument | Description |
|---|---|
| `<path>` | File or directory to validate. |

MarkApiDown classifies each file by location and name:

- Files named `env.md` → validated as environment config.
- Files under `flows/` → validated as pipeline files.
- `mad.md` and `README.md` → checked for frontmatter only.
- All other `.md` files → validated as endpoint files.

Each error message includes the file path, line number when known, and a suggested fix.

**Examples**

```bash
# Validate the entire project
mad validate api-docs/

# Validate a single endpoint file
mad validate api-docs/apis/users/get-user-by-id.md
```

**Exit codes**: `0` if all files are valid, `2` if any spec is invalid, `5` if a secret is detected.

## mad exec

Execute one endpoint file and compare the actual response against the expected response.

```bash
mad exec <file> [--env=<env>] [--output=<format>] [--var key=val]... [--dry-run] [--timeout=<ms>]
```

| Flag | Type | Default | Description |
|---|---|---|---|
| `<file>` | path | required | Path to an endpoint markdown file. |
| `--env` | string | `dev` | Environment name. Must match a heading in `_shared/env.md`. |
| `--output` | enum | `console` | Output format: `console`, `junit`, `json`, or `markdown`. |
| `--var` | string | | Inject a variable as `key=value`. Repeatable. CLI variables override all other sources. |
| `--dry-run` | bool | `false` | Print the resolved request without sending it. Makes no network connection. |
| `--timeout` | integer | | Override request timeout in milliseconds. Takes precedence over endpoint and project defaults. |

<Note>
When `--env=prod` is used in an interactive terminal, MarkApiDown prompts for confirmation before sending the request. Pass `--yes` (global flag) to skip the prompt in CI.
</Note>

If a referenced variable is not resolved from any source, MarkApiDown exits with code `2` before making any network request, and prints a suggested fix naming the variable and where to define it.

**Examples**

```bash
# Basic execution against the dev environment
mad exec api-docs/apis/users/get-user-by-id.md

# Override environment and inject a variable
mad exec api-docs/apis/users/get-user-by-id.md --env=staging --var userId=42

# JUnit XML output for CI test reporters
mad exec api-docs/apis/users/get-user-by-id.md --output=junit > results.xml

# Dry run inspect the resolved request without sending
mad exec api-docs/apis/users/create-user.md --dry-run --var email=test@example.com

# Override the timeout for a slow endpoint
mad exec api-docs/apis/users/get-user-by-id.md --timeout=10000
```

**Exit codes**: `0` response matches, `1` assertion fails, `2` invalid spec, `3` engine error, `4` network error, `5` secret detected.

## mad flow

Execute a pipeline file. Steps run sequentially by default, with optional parallelism.

```bash
mad flow <file> [--env=<env>] [--output=<format>] [--var key=val]... [--parallel] [--no-parallel] [--timeout=<ms>]
```

| Flag | Type | Default | Description |
|---|---|---|---|
| `<file>` | path | required | Path to a pipeline markdown file. |
| `--env` | string | `dev` | Environment name. |
| `--output` | enum | `console` | Output format: `console`, `junit`, `json`, or `markdown`. |
| `--var` | string | | Inject a variable as `key=value`. Repeatable. |
| `--parallel` | bool | `false` | Force parallel execution, overriding the pipeline file's `parallel` setting. |
| `--no-parallel` | bool | `false` | Force sequential execution, overriding the pipeline file's `parallel` setting. |
| `--timeout` | integer | | Override timeout in milliseconds for every step in the pipeline. |

<Warning>
`--parallel` and `--no-parallel` are mutually exclusive. Steps that depend on a captured value from a previous step always wait for that step regardless of parallel mode.
</Warning>

**Examples**

```bash
# Run a pipeline against staging
mad flow api-docs/flows/user-onboarding.md --env=staging

# Force sequential execution for debugging
mad flow api-docs/flows/user-onboarding.md --no-parallel

# JSON output for programmatic consumption
mad flow api-docs/flows/user-onboarding.md --output=json
```

**Exit codes**: `0` all steps pass (or `continue-on-error` is set), `1` any step fails, `2` pipeline spec invalid, `3` engine error, `4` network error.

## mad index

Regenerate `api-docs/README.md` from the current set of markdown files under `api-docs/`.

```bash
mad index
```

No flags. The generated file contains a linked list of all markdown files grouped by resource. Do not edit `api-docs/README.md` by hand it is overwritten on every `mad index` run.

<Note>
`mad index` is run automatically by `mad init` and by all `mad import` subcommands. Run it manually only if you added or renamed files after an import.
</Note>

**Example**

```bash
mad index
```

**Exit codes**: `0` on success, `3` on filesystem error.

## mad import

Convert an existing API spec file into MarkApiDown markdown endpoint files. All subcommands write endpoint files under `api-docs/`, then run `mad index` automatically. Complex logic (pre-request scripts, dynamic variables, JavaScript assertions) is imported as `agent-task` blocks for manual review.

**After any import**: run `mad validate api-docs/` and move any secrets to `.env.local`. See the [Migration guide](/docs/guides/migration) for per-tool concept mapping and post-import checklists.

### mad import postman

Import a Postman Collection v2.1 JSON export.

```bash
mad import postman <file>
```

| Argument | Description |
|---|---|
| `<file>` | Path to a Postman Collection v2.1 JSON file. |

```bash
mad import postman my-collection.json
```

### mad import insomnia

Import an Insomnia v4 JSON export.

```bash
mad import insomnia <file>
```

| Argument | Description |
|---|---|
| `<file>` | Path to an Insomnia v4 JSON export file. |

```bash
mad import insomnia insomnia_export.json
```

### mad import openapi

Import an OpenAPI 3.x spec in YAML or JSON format.

```bash
mad import openapi <file>
```

| Argument | Description |
|---|---|
| `<file>` | Path to an OpenAPI 3.x YAML or JSON file. |

```bash
mad import openapi openapi.yaml
mad import openapi openapi.json
```

### mad import curl

Import a single cURL command as a MarkApiDown endpoint file.

```bash
mad import curl [--file=<path>]
```

| Flag | Description |
|---|---|
| `--file` | Path to a file containing the cURL command. If omitted, reads from stdin. |

```bash
# From clipboard (macOS)
pbpaste | mad import curl

# From a file
mad import curl --file=request.curl
```

**Exit codes (all import subcommands)**: `0` on success, `2` if the input file is not a valid spec for that tool, `3` on filesystem error.

## mad skills

Install, list, or remove MarkApiDown skill files for AI coding agents. Skills are embedded in the binary no network access required.

### mad skills install

Install MarkApiDown skill files into detected AI agent config directories.

```bash
mad skills install [--agent=<name>]
```

| Flag | Type | Description |
|---|---|---|
| `--agent` | string | Install skills only for a specific agent. Installs for all detected agents if omitted. |

Supported agent names: `claude-code`, `cursor`, `copilot`, `codex-cli`, `antigravity`, `opencode`.

MarkApiDown detects agents by checking for their config directories (`.claude/`, `.cursor/`, `.github/`, etc.).

```bash
# Install for all detected agents
mad skills install

# Install only for Claude Code
mad skills install --agent=claude-code

# Install only for Cursor
mad skills install --agent=cursor
```

<Tip>
After upgrading MarkApiDown, run `mad doctor --fix` to update installed skills to the new binary version automatically.
</Tip>

### mad skills list

List detected AI agents and whether MarkApiDown skills are installed and up-to-date for each.

```bash
mad skills list
```

No flags.

```bash
mad skills list
# claude-code: detected, skills up-to-date
# cursor: not detected
# copilot: not detected
```

### mad skills uninstall

Remove installed MarkApiDown skill files.

```bash
mad skills uninstall [--agent=<name>]
```

| Flag | Type | Description |
|---|---|---|
| `--agent` | string | Uninstall skills for a specific agent only. Uninstalls for all agents if omitted. |

```bash
mad skills uninstall --agent=claude-code
```

**Exit codes (all skills subcommands)**: `0` on success, `3` on filesystem error.

## mad serve

Start the local web preview server.

```bash
mad serve [<path>] [--port=8080] [--host=127.0.0.1] [--env=<env>] [--mock]
```

| Flag / Argument | Type | Default | Description |
|---|---|---|---|
| `<path>` | path | `.` (current directory) | Root directory of the MarkApiDown project. |
| `--port` | integer | `8080` | TCP port to listen on. |
| `--host` | string | `127.0.0.1` | Host to bind to. Use `0.0.0.0` to expose on the local network (a warning is printed). |
| `--env` | string | `dev` | Environment used when executing endpoints from the preview UI. |
| `--mock` | bool | `false` | Start in mock mode. The "Send" button returns the recorded `## Expected response` instead of making a real HTTP request. |

The web preview reads the same markdown files as the CLI. No build step is required. The server watches for file changes and refreshes connected browsers automatically.

```bash
mad serve
mad serve --port=9000 --env=staging
mad serve --mock
mad serve /path/to/other-project
```

**Exit codes**: `0` on clean shutdown (Ctrl-C), `3` on startup error.

## mad doctor

Check the project environment for common setup problems.

```bash
mad doctor [--fix]
```

| Flag | Type | Description |
|---|---|---|
| `--fix` | bool | Automatically apply safe fixes. |

`mad doctor` checks:

- Whether `api-docs/` exists.
- Whether `.env.local` is listed in `.gitignore`.
- Whether all specs under `api-docs/` are valid.
- Which AI agent config directories are present.
- Whether installed skills match the current binary version.
- Whether an outbound network connection can be made.

`--fix` applies safe fixes automatically: adds `.env.local` to `.gitignore` if missing, and reinstalls stale skills.

<Note>
Run `mad doctor` as the first debugging step when `mad exec`, `mad validate`, or an AI agent skill behaves unexpectedly.
</Note>

```bash
mad doctor
mad doctor --fix
```

**Exit codes**: `0` if all checks pass, `1` if any check fails.

## mad mock

Start a mock HTTP server that replays recorded expected responses.

```bash
mad mock [<path>] [--port=4001] [--latency=<ms>]
```

| Flag / Argument | Type | Default | Description |
|---|---|---|---|
| `<path>` | path | `.` (current directory) | Root directory of the MarkApiDown project. |
| `--port` | integer | `4001` | TCP port to listen on. |
| `--latency` | integer | `0` | Simulated response latency in milliseconds. |

The mock server reads `## Expected response` blocks from your endpoint files and serves their bodies at the corresponding HTTP methods and paths. Useful for frontend development when the live backend is unavailable.

```bash
# Start mock server on default port
mad mock

# Simulate network latency
mad mock --port=4001 --latency=200
```

## mad mcp

Start a Model Context Protocol server that exposes MarkApiDown tools to AI agents.

```bash
mad mcp
```

No flags. The MCP server exposes the following tools to any MCP-compatible AI agent:

| Tool | Description |
|---|---|
| `mad_exec` | Execute an endpoint spec |
| `mad_flow` | Run a pipeline |
| `mad_validate` | Validate specs in a file or directory |
| `mad_list_specs` | List all endpoint specs with method and path |
| `mad_read_spec` | Read the full content of a spec file |
| `mad_author` | Create or update a spec file |

Register with Claude Code:

```bash
claude mcp add mad -- mad mcp
```

See [AI agent integration](/docs/guides/ai-agents) for full setup and usage details.

## mad completion

Print a shell completion script to stdout.

```bash
mad completion <shell>
```

| Argument | Description |
|---|---|
| `<shell>` | One of `bash`, `zsh`, `fish`, `elvish`, or `powershell`. |

<CodeGroup>

```bash Bash
mad completion bash >> ~/.bash_completion
```

```bash Zsh
mad completion zsh > ~/.zfunc/_mad
echo 'fpath=(~/.zfunc $fpath)' >> ~/.zshrc
autoload -Uz compinit && compinit
```

```bash Fish
mad completion fish > ~/.config/fish/completions/mad.fish
```

</CodeGroup>

**Exit codes**: `0` always.
